# Pool:案件管理系統

## 角色(泳道)

1. 使用者

## 流程步驟

1. **開始**(起始事件|角色:使用者)
2. **執行分案**(任務|角色:使用者)
3. **傳送執行案號、確認案號、被告姓名、身分證號至AI智慧輔助系統**(任務|角色:使用者)
4. **使用者於案件管理系統執行分案時,將執行案號、確認案號、被告姓名、身分證號傳給AI智慧輔助系統作為撈取判讀依據**(註解|角色:使用者)
5. **轉AI智慧輔助系統**(結束事件|角色:使用者)

## 流程連線

- 開始 → 執行分案
- 執行分案 → 傳送執行案號、確認案號、被告姓名、身分證號至AI智慧輔助系統
- 傳送執行案號、確認案號、被告姓名、身分證號至AI智慧輔助系統 → 轉AI智慧輔助系統

# Pool:AI智慧輔助系統

## 角色(泳道)

1. 系統

## 流程步驟

1. **接收案件資料**(起始事件|角色:系統)
2. **依確認案號至司法院裁判書系統查詢下載裁判書**(任務|角色:系統)
3. **AI判讀裁判書七項欄位**(任務|角色:系統)
4. **RFP工項:裁判書API判讀七項欄位(正確率80%);駁回?→是取原案(上一審)確認案號重查上一審裁判書,→否即有裁判結果以此版本分辨**(註解|角色:系統)
5. **駁回?**(排他閘道|角色:系統)
6. **以確認案號+被告姓名取得相關欄位資訊,整理判讀結果**(任務|角色:系統)
7. **取原案(上一審)確認案號,重查取得上一審裁判書**(任務|角色:系統)
8. **以執行案號+被告姓名+身分證號回傳,呼叫刑案管理系統API存入暫存檔**(任務|角色:系統)
9. **欄位判讀結果**(輸出文件|角色:系統)
10. **回傳刑案管理系統**(結束事件|角色:系統)
11. **AI判讀完個案欄位屬性後,以執行案號+被告姓名+身分證號呼叫刑案管理系統API將判讀結果寫入暫存區;使用者點選AI引用時由系統自暫存區讀取(RFP工項要求API整合)**(註解|角色:系統)

## 決策點

- **駁回?**(排他)
  - （上訴駁回→否） → 以確認案號+被告姓名取得相關欄位資訊,整理判讀結果
  - （上訴駁回→是） → 取原案(上一審)確認案號,重查取得上一審裁判書

## 流程連線

- 接收案件資料 → 依確認案號至司法院裁判書系統查詢下載裁判書
- 依確認案號至司法院裁判書系統查詢下載裁判書 → AI判讀裁判書七項欄位
- AI判讀裁判書七項欄位 → 駁回?
- 駁回? —[上訴駁回→否]→ 以確認案號+被告姓名取得相關欄位資訊,整理判讀結果
- 駁回? —[上訴駁回→是]→ 取原案(上一審)確認案號,重查取得上一審裁判書
- 取原案(上一審)確認案號,重查取得上一審裁判書 —[重查]→ 依確認案號至司法院裁判書系統查詢下載裁判書
- 以確認案號+被告姓名取得相關欄位資訊,整理判讀結果 → 以執行案號+被告姓名+身分證號回傳,呼叫刑案管理系統API存入暫存檔
- 以執行案號+被告姓名+身分證號回傳,呼叫刑案管理系統API存入暫存檔 → 回傳刑案管理系統

# Pool:刑案管理系統

## 角色(泳道)

1. 使用者

## 流程步驟

1. **AI判讀結果已寫入暫存區**(起始事件|角色:使用者)
2. **登入刑案管理系統**(任務|角色:使用者)
3. **進入執行類案件查詢個案**(任務|角色:使用者)
4. **點選「AI引用」按鈕**(任務|角色:使用者)
5. **自暫存區讀取AI判讀結果**(任務|角色:使用者)
6. **檢視判讀資料是否符合需求**(任務|角色:使用者)
7. **引用→否時由統計處收集不符資訊,回饋進行判讀邏輯調整**(註解|角色:使用者)
8. **引用?**(排他閘道|角色:使用者)
9. **點選引用,欄位資訊存入刑案管理系統**(任務|角色:使用者)
10. **結束**(結束事件|角色:使用者)

## 決策點

- **引用?**(排他)
  - （引用→否） → 結束
  - （引用→是） → 點選引用,欄位資訊存入刑案管理系統

## 流程連線

- AI判讀結果已寫入暫存區 → 登入刑案管理系統
- 登入刑案管理系統 → 進入執行類案件查詢個案
- 進入執行類案件查詢個案 → 點選「AI引用」按鈕
- 點選「AI引用」按鈕 → 自暫存區讀取AI判讀結果
- 自暫存區讀取AI判讀結果 → 檢視判讀資料是否符合需求
- 檢視判讀資料是否符合需求 → 引用?
- 引用? —[引用→否]→ 結束
- 引用? —[引用→是]→ 點選引用,欄位資訊存入刑案管理系統
- 點選引用,欄位資訊存入刑案管理系統 → 結束
